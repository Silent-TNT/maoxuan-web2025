## 检索：按问法分两类标定

真实问题与正文块的 top1 余弦实测 0.42–0.68，与"块和块"相似度（中位 0.68）不是同一分布。原先阈值 0.78/0.84 高于整个取值范围，向量通道等于关闭。

| 问法 | 绝对下限 | 相对窗口 | 是否重排 |
| --- | --- | --- | --- |
| 找篇名/原句（含《篇名》、原文、出处、毛选…） | 0.50 | top1 − 0.005 | 否（词法锚点更可靠） |
| 生活问法（几乎不含原著词汇） | 0.42 | top1 − 0.015 | 是，两级：块级重排（20 条 × 260 字，约 300ms）+ 引文级重排（前 4 篇 × 最多 24 句，约 300–450ms） |

引文不再按词面挑：块级重排定篇目顺序后，再用同一个重排模型给"这一句能不能回答读者的问题"打分，每篇取最相关的 3 句。若块级重排刚因超时降级过，就不再追加引文重排，避免首字被拖长（`RAG_QUOTE_RERANK=0` 可整体关闭）。

生活问法走两段式召回：融合头部 12 条 + 向量宽召回（最多 24 条，要求 ≥ max(0.30, top1−0.25)，避免把噪声塞进重排）拼成约 44 条的候选池，整体重排后再按篇目取引文。

- 「相邻块扩展」已实现（`RAG_NEIGHBOR_SPAN=1` 可开），但在这套题集上没有任何增益（9/20 → 9/20），默认关闭：它只会让重排多打分、没有带进新的正确段落。

融合与重排的两条保护：
- **dense 按篇目去重**后再融合：同一篇只贡献一个块，避免一篇挤掉别的篇（默认开，`RAG_DENSE_PATH_DEDUPE=0` 可关）。
- **词法锚点前置**：读者点名某篇或选中原文时命中的块（`pinned`）排在重排之前，保证不会被语义重排挤掉。
- 重排候选池默认 20 条（`RAG_RERANK_CANDIDATES` 可调；实测 12 条时生活题 6/20，20 条 7/20，28 条反而让咨询题掉一题）；送进重排的文本截到 260 字（`RAG_RERANK_DOC_CHARS`），比 420 字快约 300ms 且生活题命中更好。

向量服务超时 1.0 秒；rerank 超时 1.2 秒，失败即保持融合顺序。可用 `RAG_DENSE_FLOOR`、`RAG_DENSE_WINDOW`、`RAG_DENSE_WEIGHT`、`RAG_RERANK_DISABLED` 覆盖。

生活题的天花板已经不在"挑哪句"或"多给几个位置"：topK 提到 6/7、候选池扩到 30/56、每篇引文加到 4–5 句，排序指标都不再涨。这轮真正有效的是两段式召回（篇目 7→9、引文 2→3），因为把"预期那句所在的块"从宽召回里捞进了候选池。top1/MRR 有 ±1 的波动，来源是重排偶发超时降级（网络），召回数稳定。

生活题集是这轮新增的（`scripts/rag/eval-life-questions.json`）：20 道口语化提问，预期引文都验证过"在正文里、也在渲染页上"。它把"向量到底有没有用"从猜测变成可测：纯关键词在这些题上**全军覆没**，向量 + 重排能把篇目命中拉到 6/20。绝对水平仍低，是下一步 rerank/candidates 调优的基线。

## 引用守卫

规则：只拦"冒充原文"。段落明确归到「原话/原文/写道：“”」时，**四种引号（“”『』「」）都核对**编号与来源——真机发现模型会用「」引原文来绕过"只核对“”"的规则，已补上；只是《篇名》讲道理的转述，只核对"篇名与编号是否一致"；否认归属的段落一律保留（含"不是《矛盾论》里的原话"这种带"里"的写法）；「」用来复述读者自己的话时，不参与核对。删段后折叠空行；正文被删到只剩一句动作时，用「核不着」兜底；删除量通过 `guard` 字段返回。

回归用例覆盖：普通强调引号、否认段落、冒充原文、篇名与编号错配、真引文、删空兜底、长回声不误删。

## 回答策略：有据才引 → 分三档说话

原先提示词要求"方法框架留在心里""正文别按方法名称汇报"，结果生活题既没有引用、也不点方法名，读起来像通用生活建议，不像"拿书里的道理说话"。现在改成三档：

1. 摘录里有一句贴切的 → **必须引**（至少一处）；
2. 只有方法对得上、没有贴切原句 → **点一次方法名**（这是调查研究 / 先抓主要矛盾 / 内外因分开看），用日常话讲；
3. 连方法都对不上 → 只回应当下处境，不硬套书里的词。

真机对照（30 题，`--chat`，同一套检索）：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 有据（引用或点方法名） | 16/30（53%） | **20/30（67%）** |
| 点明方法 | 7 次 | **14 次** |
| 引用原文 | 12 | **14** |
| 该引没引 | 1 | **0** |
| 误引 | 0 | 0 |
| 回答中位字数 | 281 | 296 |
| 首字中位 | 1281ms | 1434ms |

同时修掉一个守卫误删：段落里既有《实践论》归属、又有读者回声「小实验」时，整段被当成伪造引文删掉。现在只有"像一整句"的 `「」` 才参与核对，短回声不核对。

## 对话体验

- 动作连续性：首轮禁止预设前情的动作；后续轮要求接着上一轮做；上一条已用过动作时，这一条开头的动作直接去掉（流式阶段也不推送）。
- **方法轮换**：提示词会带上"上一两回已经点过的方法名"，要求这一轮换一种、或只讲具体做法不点名。三轮实测依次为：调查研究 → 主要矛盾 → 实践检验，没有连着重复。
- **引用多样性**：同一段话只取一句当依据（避免把一段拆成三条）；生活问法每篇只取一条依据，逼出跨篇引用。
- **上游断连重试**：真机出现过 `[chat] stream failed: fetch failed`（到 DeepSeek 的连接中断，前端显示"刚才那句话我没接上"）。现在流式请求在拿到任何字节之前失败会自动重试一次（300ms 间隔）。
- 事实卡：从读者原话抽带数量的处境与身份/状态/卡点线索（三个月、两周、裁员、房贷…），同一项以最近一次为准，随每次请求发送。
- 无依据时不再输出「这一轮没找到原文」这类系统旁白；证据面板标题改为「翻到的原文 · N 处」。
- 原文高亮：点「查看《…》全文」后，按文本节点字符区间把那一句包成 `<mark>` 并滚动过去；分享链接只带截断的引文时，也会补全到句末。真浏览器验证：61 字长句完整高亮、正文不丢字。
- 首字：内部开销 0.3–0.5 秒（规划 ≤300ms、向量 ≤1s）；实测上游 DeepSeek 首句 144ms–3.9 秒，抖动主要来自服务端。

## 评测命令

| 命令 | 用途 |
| --- | --- |
| `npm run rag:test-citations` | 引用、守卫、记忆、规划、中断的模拟回归 |
| `npm run rag:eval` | 默认路径：原著题、咨询题、生活题、MRR/top1 |

## 工程侧

- `/api/chat` 限流：每 IP 12 次/分钟（dev 放宽 60），请求体 >200KB 直接拒绝；配 `UPSTASH_REDIS_REST_URL/TOKEN`（或 Vercel KV 变量）时走 KV 共享计数，未配置则单实例内存计数。被限流时前端显示教员口吻的提示。
- `vercel.json` 增加 `maxDuration: 60`。
- 触屏设备回车换行、`Ctrl/⌘+Enter` 发送；桌面回车直接发送。
